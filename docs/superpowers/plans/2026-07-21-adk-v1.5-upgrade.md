# Google ADK v1.2.0 → v1.5.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move omnis from `google.golang.org/adk v1.2.0` to `v1.5.0` (and the transitive `genai v1.40.0 → v1.57.0` bump it forces) without regressing any runtime behaviour.

**Architecture:** This is a **dependency upgrade + verification** plan, not a feature build. Investigation (recorded below) proved the change is **source-backward-compatible** for every ADK symbol omnis consumes — ADK performed its "context unification" with type aliases + deprecated forwarding shims, and every constructor/interface omnis touches is unchanged or additively extended. A full trial bump already **built clean, compiled all test binaries, passed `go vet`, passed all 52 unit-test packages, and passed the `-race` regressions**. The residual risk is therefore **runtime/behavioural**, concentrated in `core/llm` (which constructs `genai` types directly and is exercised only against a live gateway, not unit tests). The plan front-loads the mechanical bump, then spends its weight on live-surface verification and a short list of ADK behavioural deltas.

**Tech Stack:** Go 1.25.5, `google.golang.org/adk`, `google.golang.org/genai`, the ChapsVision LiteLLM gateway (per project memory), `../omnis-benches` (`model-probe`, `squad-bench`).

## Global Constraints

- **Branch first.** Current branch is `main`; the repo's PR target is `develop`. Do all work on a feature branch, never commit upgrade work directly to `main`.
- **Version floor:** `google.golang.org/adk v1.5.0` exactly (latest stable as of 2026-07-21); let `go mod tidy` resolve transitive deps (it pins `genai v1.57.0`, `grpc v1.81.0`, `otel v1.43.0`, `x/net v0.55.0`, adds `gonum v0.17.0`).
- **No `replace` directives** for adk/genai — omnis has none today; keep it that way.
- **Do not vendor or fork ADK.** omnis imports only ADK *public* packages; it holds a *local reimplementation* of the one unexported helper it needs (`packToolDecl`, a copy of `toolutils.PackTool`). Do not add ADK-internal imports.
- **This is internal plumbing — NOT a user-facing feature.** Per `CLAUDE.md`, do **not** add a `internal/features/FEATURES.md` bullet. Documentation lives in `CLAUDE.md` (path-reference refresh only).
- **Commit message trailer:** end every commit with `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- **Benchmarks/eval tooling live only in `../omnis-benches`** — never add bench code to this repo.

## Investigation Findings (evidence the tasks rely on)

Recorded 2026-07-21 by diffing the module cache (`$GOMODCACHE/google.golang.org/adk@v1.2.0` vs `@v1.5.0`) and running a reversible trial bump. **An executor should trust these but re-confirm via the Task 1 gates.**

### Compile-time: fully backward-compatible

| ADK symbol (uses in omnis) | v1.2.0 → v1.5.0 | Impact |
|---|---|---|
| `tool.Context` (163) | Became `type Context = agent.ToolContext` (**alias**); method set identical (`FunctionCallID`/`Actions`/`SearchMemory`/`ToolConfirmation`/`RequestConfirmation` + embedded `CallbackContext`) | None — alias keeps all uses valid |
| `agent.CallbackContext`/`ReadonlyContext`/`InvocationContext` (context types) | **Byte-identical** | None |
| `llmagent.BeforeToolCallback`/`AfterToolCallback`/`OnToolErrorCallback` (31) | Param type `tool.Context` → `agent.ToolContext` — **same type via the alias**, so omnis funcs typed `func(ctx tool.Context, …)` still satisfy them | None |
| `llmagent.BeforeModelCallback`/`AfterModelCallback` (21) | Identical (`agent.CallbackContext`) | None |
| `plugin.OnUserMessageCallback`/`BeforeRunCallback`/`AfterRunCallback`, `plugin.Plugin`/`New`/`Config` | Identical | None |
| `functiontool.New`/`Config`/`Func` (112) | `Func` param `tool.Context`→`agent.ToolContext` (alias); `New`/`Config` identical; `NewStreaming` is additive | None |
| `agenttool.New`/`Config` (6) | Identical (incl. `Config.SkipSummarization`) | None |
| `runner.New`/`Run`/`Config`/`PluginConfig` (36) | **`Run` signature byte-identical**; `RunLive` additive | None |
| **`model.LLM` interface (omnis implements it in `core/llm`)** | `Name()` + `GenerateContent(ctx, *LLMRequest, stream bool) iter.Seq2` **byte-identical**; `LLMRequest`/`LLMResponse` identical | None (adapters still satisfy the interface) |
| `session.Service`/`CreateRequest`/`GetRequest`/`DeleteRequest`/`NewEvent`/`InMemoryService` (many) | Identical; `NewEventWithContext` additive | None |
| `skilltoolset`, `mcptoolset`, `memory`, `artifact`, `model/gemini` | No consumed-symbol changes | None |

**No ADK `internal/*` imports** (Go forbids them; the `base_flow.go`/`toolutils` references in `CLAUDE.md` are behavioural notes + a local copy). **No `adk/a2a` import** (omnis ships its own A2A client). **No ADK HITL usage** (`RequestConfirmation`/`ToolConfirmation` — grep returns nothing; omnis uses its own permission gate).

### Behavioural assumptions re-verified against v1.5.0 source

- **`SkipSummarization` → `IsFinalResponse()` → flow loop stops** — the load-bearing termination trick behind the router (`route_to_squad`/`handoff_to_router`), `report_sessions`, and the per-agent cap. v1.5.0's `agent/callback_context.go` documents this exact mechanism verbatim → **still valid**.
- **omnis owns its ADK sessions** (`session.InMemoryService` + `Create`/`Delete`/`AppendEvent`, explicit `userID`/`sessionID` to `runner.Run`). The v1.3.0 runner session auto-creation (#754) and v1.5.0 manual-session-ID (#721) changes don't alter the signature omnis calls; the reseed/fork/rewind tests pass unchanged.

### ADK behavioural deltas that DON'T touch omnis (dismissed with evidence)

- **a2a-go/v2 migration** (v1.3.0/v1.4.0): omnis has no ADK-a2a / a2a-go dependency (`grep -iE 'a2a|trpc' go.mod` → none).
- **HITL confirmation ordering** (#765/#763/#767): omnis doesn't use ADK HITL.
- **`StreamingResponseAggregator` accepts metadata-only SSE chunks** (#918): a fix *inside* ADK's flow consuming omnis's `LLMResponse` stream — neutral-to-positive.

### The ONE real residual risk: `genai v1.40.0 → v1.57.0` (17 minors)

`go mod tidy` pulls `genai v1.57.0` as an ADK v1.5.0 requirement. `core/llm/{anthropic,openai,gemini,convert}.go` construct/serialize `genai.Content`/`Part`/`FunctionCall`/`GenerateContentConfig`/usage metadata directly. **It compiled clean and all unit tests passed**, which proves no removed/renamed symbols — but unit tests do not hit the live gateway, so *runtime serialization semantics* (streaming tool-call arg assembly, `cache_control` prompt-cache annotation, `cached_tokens`/reasoning-token usage mapping, parameterless-tool-over-streaming — the historical GLM bug) are the thing Task 2/Task 3 must actually exercise.

- [ ] **Step 1: Prompt-cache `cache_control` annotation still honoured**

- [ ] **Step 2: Usage mapping — `cached_tokens` + reasoning tokens**

ADK v1.3.0 (#779) renamed the reasoning-token telemetry attribute and changed `gen_ai.usage.output_tokens` semantics. omnis reads usage via `usage.prompt_tokens_details.cached_tokens` (`core/llm/openai.go` `cachedRead`) for the cache-stats plugin.

Expected: no change needed. If reasoning-token accounting is now double-counted in output tokens, note it (cost display only — non-fatal).

- [ ] **Step 3: Streaming tool-call argument assembly (the GLM-class risk)**

The historical failure mode (project memory: GLM-5.2) is a backend dropping `tool_calls` when streaming with parameterless tools; omnis buffers tool-call arg fragments in `core/llm/openai.go` `streamSSE`. model-probe's "parameterless tool over streaming" check (Task 2 Step 1) is the exact regression probe.
Expected: pass. If it fails on a model that previously worked, the `genai`/adapter streaming-aggregation contract changed — compare `streamSSE` fragment handling against ADK's `StreamingResponseAggregator` (#918 now accepts metadata-only chunks) and adjust.

- [ ] **Step 4: Session lifecycle unchanged**
